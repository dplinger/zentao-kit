# 按人查询：我的地盘（`mine`）

`mine` 命令走禅道「我的地盘」页面，回答「**我的** X 有哪些」。REST 查不到这类问题：`query --entity stories` 必须给产品编号，而 `v1/tasks`、`v2/tasks`、`v2/my/*` 实测一律 403——禅道 REST 里没有「我」这个资源。

```text
python <技能目录>/scripts/zentao.py mine                             # 列出可用视图
python <技能目录>/scripts/zentao.py mine --entity stories            # 指派给我的需求
python <技能目录>/scripts/zentao.py mine --entity stories --scope openedBy   # 我创建的需求
python <技能目录>/scripts/zentao.py mine --entity testtasks          # 我的测试单
python <技能目录>/scripts/zentao.py mine --entity stories --all      # 取全部（不截断）
```

## 可用视图与归属范围

| `--entity` | 含义 | `--scope` |
|---|---|---|
| `stories` | 需求 | `assignedTo` 指派给我（默认）/ `openedBy` 我创建 / `reviewedBy` 我评审 / `closedBy` 我关闭 |
| `testtasks` | 测试单 | 只有 `assignedTo`（指派给我） |

`--limit` 默认 20、上限 200；`--all` 取全部。输出含记录条数、归属范围说明与每条记录的详情页链接。

## ⚠️ 安全前提：非法范围会让服务端返回所有人的数据

实测（企业版 12.7）：把 `--scope` 换成一个不存在的值，服务端**不报错**，而是**返回全量**——

| 请求 | 结果 |
|---|---|
| `/my-work-story-assignedTo-…` | 0 条（正确：没有被指派给我的需求） |
| `/my-work-story-zzznotascope-…` | **20 条别人创建的需求** |
| `/my-work-testtask-assignedTo-…` | 1 条（我的） |
| `/my-work-testtask-owner/createdBy/任意值-…` | **返回全部记录** |

也就是说，问「我的需求」可能拿到**全公司的需求**——这是本项目里最危险的一类错数据（比报错严重得多）。

因此 `mine` 做两层防护，两层都不依赖服务端诚实：

1. **`--scope` 一律取自本地白名单**，绝不把用户输入拼进 URL；写错立刻报错并列出可用值。
2. **逐条核对归属字段**必须等于当前登录账号，对不上就报错停止。万一服务端哪天改了行为，第二条也能拦住。

宿主不得绕过脚本自行拼这些 URL 试探，也不要因为「返回 200」就认为结果正确。

## 与 `query` 的分工

| | `query` | `mine` |
|---|---|---|
| 问法 | **按对象**：某产品/项目/执行下有什么 | **按人**：分给我 / 我创建 / 我评审的有什么 |
| 链路 | REST | 「我的地盘」页面 JSON |
| 前提 | 必须给出范围编号 | 用当前登录身份，无需编号 |
| 跨版本 | 有版本承诺（v1 ≥ 16.5、v2 ≥ 21.7.8） | 页面链路，无版本承诺（见 [禅道接口说明](禅道接口说明.md) 的链路选择） |

`bugs` 命令（我的 Bug，支持指派给我 / 我创建 / 我解决 / 我关闭四个归属）与本命令是同一类，只是更早实现；候选任务 `candidates` 也走同一个页面通道。

## 能力边界

- **我的用例：不提供**。该视图对任何范围参数都返回 0 条，无法确认哪个参数有效——与其接一个可能返回错数据的入口，不如不做。
- **空结果就是空结果**：某个归属下没有记录时返回 0 条，不代表查询失败。反过来，若服务端返回了不属于当前账号的记录，脚本会直接报错停止，不会把别人的数据当成你的。
