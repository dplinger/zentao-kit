# 产品、项目、执行操作

用「预览 → 用户确认 → 单次写入 → 回查」两步完成产品、项目、执行的**新建与修改**。三者走同一套流程，命令换前缀即可。

> **权限要求**：三者的写操作通常属**管理员或产品经理角色**。没有权限时接口返回 HTTP 403，
> 脚本会明确提示「当前账号没有××的写权限，请管理员授权」，请如实转达，
> 不要压缩成「操作失败」。

```text
python <技能目录>/scripts/zentao.py product-prepare   --plan <plan路径>   # 只读，生成预览
python <技能目录>/scripts/zentao.py product-submit    --review <完整摘要> --confirm <同一完整摘要>
python <技能目录>/scripts/zentao.py project-prepare   --plan <plan路径>
python <技能目录>/scripts/zentao.py project-submit    --review <完整摘要> --confirm <同一完整摘要>
python <技能目录>/scripts/zentao.py execution-prepare --plan <plan路径>
python <技能目录>/scripts/zentao.py execution-submit  --review <完整摘要> --confirm <同一完整摘要>
```

## 计划格式

`create` 不需要编号；`update` 的编号键与实体同名（`product` / `project` / `execution`）。

```text
{"action":"create","fields":{"name":"新产品","code":"NEWPROD","PO":"your-account","type":"normal"}}
{"action":"update","product":84,"fields":{"name":"新名字","status":"closed"}}
{"action":"create","fields":{"name":"新项目","begin":"2026-10-16","end":"2026-12-31","products":[1],"PM":"your-account"}}
{"action":"update","project":8,"fields":{"name":"改过的项目名","end":"2026-12-31"}}
{"action":"create","fields":{"name":"迭代一","begin":"2026-10-16","end":"2026-11-16","project":8,"PM":"your-account"}}
{"action":"update","execution":2,"fields":{"name":"开发","status":"suspended"}}
```

## 端点与字段

| 实体 | 新建 | 修改 | 必填（仅新建时） |
|---|---|---|---|
| 产品 | `POST v1/products` | `PUT v1/products/{id}` | `name` |
| 项目 | `POST v1/projects` | `PUT v1/projects/{id}` | `name`、`begin`、`end`、`products` |
| 执行 | `POST v1/projects/{project}/executions` | `PUT v1/executions/{id}` | `name`、`begin`、`end`、`project` |

**可用字段**

- 产品：name、code、program（项目集）、line、PO、QD、RD、type（`normal`/`branch`/`platform`）、desc、acl（`private`/`open`/`custom`）、whitelist；修改另支持 status（`normal`/`closed`）。
- 项目：name、code、begin、end、products（产品编号数组）、parent（项目集）、PM、model（`scrum`/`waterfall`/`kanban`/`agileplus`/`waterfallplus`/`ipd`）、acl、desc、whitelist、multiple（`on`=`多迭代`，`no`=`单迭代`，不填即单迭代）、storyType；修改另支持 days、budget、budgetUnit、workflowGroup。
- 执行：name、code、begin、end、project、lifetime（`0`/`1`）、desc、days、percent、parent、acl、PO、PM、QD、RD、whitelist、products、plans、teamMembers；修改另支持 status。

**默认值**：未指定时 `acl=private`；项目未指定 `model` 时按 `scrum` 创建、`storyType` 由模型推导。

## 两处源码级的坑

- **项目的项目集要用 `parent`，不是 `program`**。条目源码里 `setPost('parent', request('program', 0))` 紧接着被 `setPost('parent', request('parent', 0))` 覆盖，`program` 参数实际无效。产品那边的 `program` 是有效的——两者不一致，不要凭直觉类推。
- **执行创建的 `project` 只认路径参数**（源码 `$this->param('project')` 读的是路径或 query），放 JSON body 里会被忽略并覆盖成 0。脚本已改为走 `v1/projects/{project}/executions`。

## 关联编号会先预检

实测教训：接口对写错的编号未必报错。脚本在预览阶段就验证：

- 项目/执行/产品的 `program`、`parent` → 项目集必须存在
- 项目的 `products`、执行的 `products` → 产品必须存在
- 执行的 `project` → 项目必须存在

不存在时当场报错，不发写入请求。

## 权限：403 就是权限不足

**产品、项目、执行的写权限通常属管理员或产品经理角色。** 脚本遇到 403 会明确说明，例如：

> 当前账号没有项目的写权限（HTTP 403），本次操作未执行。项目的创建与修改通常属管理员或产品经理角色权限，请让禅道管理员为该账号授予相关权限后重试。

**如实转达这条提示**，不要压缩成「操作失败」。脚本已保留操作记录，不会自动重发。

## 写入后的处理

- 写入前重新读取实时详情与预览时的指纹比对；**预览后被人改过就拒绝写入**并要求重新预览。
- 写入后重新读取详情核对**本次请求的字段**（项目名称、日期、指派人、关联编号等）。**不核对未请求的字段**——这些实体有大量服务端派生的字段（进度、工时、子项统计），逐项核对必然误报。
- 日期范围会连同服务端保留的旧值一起复核，避免「只改结束日期」时把范围改倒。
- 结果不明（超时、响应异常）时保留收据并**禁止重发**，只能只读回查。同一份预览不允许执行两次。
- 不提供删除产品、项目、执行的能力。
