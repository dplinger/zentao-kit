# 登录与交互

## 外部登录

`zentao.py auth` 从用户提供的站点（个人 `preferences.json`、`ZENTAO_BASE_URL` 或 `--base-url`）启动后台 Python，仅监听 127.0.0.1 随机端口，打开默认浏览器。用户本人输入后，通过 POST v2/users/login 获取令牌、用户信息和 Cookie，并核对返回账号。页面显示目标站点。

## 站点地址

技能**不内置任何默认站点**，地址由用户提供，保存于个人 `preferences.json`。

- 未配置时 `auth` / `configure` 返回 `NEED_BASE_URL`，宿主据此向用户**一次性**索取地址；不要逐项追问。
- 地址解析对写法宽容：去除 `index.php`/`api.php`/`api.php/v1` 等入口后缀与尾部斜杠，去掉粘贴带入的引号和空白；缺协议时 HTTPS 优先、HTTP 兜底。只给域名时会自动追加并探测 `/zentao` 子目录。
- 落盘前先探测 `{站点}/api.php/v1/ping`（200 或 401 视为入口存在），**探测不通过当场报错**，不进入登录页，避免用户白输一遍账号密码。
- **协议策略**：HTTPS 优先。用户显式给 `http://` 时也会先试同址 HTTPS，能用就自动升级并说明；只能走 HTTP 时如实放行，并在配置结果与每次登录成功消息中给出「账密与令牌明文传输」告警。显式给 `https://` 时不会降级。带账号密码、查询参数或片段的地址一律拒绝。
- **探测失败要区分原因**，分别给出可行动的建议：证书不受信任（自签名常见 → 把站点 CA 装入系统信任库，或改用 HTTP 地址）、网关或代理异常（502/503/504，也可能是本机代理无法访问该地址 → 稍后重试或把该地址加入代理直连）、地址可达但没有接口入口（核对子目录与站点类型）、网络不通（核对拼写、端口、可达性）。**不提供跳过证书校验的开关，TLS 校验始终开启。**
- 以上失败原因写在脚本 `message` 里，**必须原样转达用户，不得概括成「连接失败」**——提示里已经写明原因和建议动作，概括掉就等于让人去瞎试。
- 切换站点：`configure --base-url <地址>` 后必须重新登录。

- 密码不进命令参数、环境变量或输出；成功登录后只将账密密文写入个人状态文件。账密以**本机随机密钥**加密（`scripts/local_cipher.py`，只用标准库），密钥优先由操作系统凭据保护（Windows DPAPI / macOS 钥匙串），不写进代码，所以「记住账密 + 令牌过期自动重登」始终可用，且换机器解不开。登录成功后的提示会如实说明密钥由谁保护。登录请求不携带示例旧令牌、不允许重定向。
- 随机路径、防跨站令牌、Host/Origin 检查、禁缓存、禁嵌入、无第三方脚本。
- 成功或10分钟超时后退出。登录窗口未结束时不再创建同一登录；换站点先结束旧流程。
- auth 启动后会在最多6秒内回查本机监听端口；只有服务仍可访问时才返回 url。auth-wait --seconds 20 有界等待，宿主保持当前任务运行并连续等待，成功后自动 whoami 再继续，不要求用户回复已登录。无论自动打开是否成功，都展示返回 url 为“打开登录页”链接。
- 始终先执行 `whoami`。令牌过期时脚本自动重登一次；仅返回 `AUTH_REQUIRED` 时进入人工登录。**默认用浏览器登录页**：执行 `auth`，把返回的链接交给用户本人打开并输入账号密码。若宿主会在命令结束时回收子进程（WorkBuddy 属于此类：`auth` 返回 `waiting` 后十几秒页面就不可访问），改为**后台运行 `auth --wait`** 并用 `auth-wait` 轮询，不要因此放弃浏览器改走终端。仅当后台任务已经退出、页面持续不可达或网页明确失败时，才执行一次 `auth --terminal-window` 兜底。该命令按操作系统在 Windows Terminal/独立控制台、macOS Terminal 或常见 Linux 终端中自动运行登录命令，用户只需输入账号密码。macOS 通过 `~/.zentao-worklog/zentao-login.command` 启动，不依赖宿主的“自动化控制 Terminal”权限，并支持中文及空格路径。若无法调起，提示用户在自己的独立终端运行 `auth --terminal`。终端密码输入可见，用户应避免旁观或屏幕共享；禁止 AI 通过工具 stdin 代填或读取凭据。

## 缓存边界

`~/.zentao-worklog/auth-status.json` 统一存登录进度、明文访问令牌、Cookie、用户 id/account/realname 及账密密文；同目录 `login.key` 是解密账密用的密钥（系统凭据保护后的 blob，或降级时的明文）；旧版需重新登录，新登录成功后自动删除旧 session.json，预览在 `~/.zentao-worklog/reviews/`，提交收据在 `~/.zentao-worklog/receipts/`，与技能代码分开存放：

- **密钥优先交给操作系统凭据保护**：Windows 用 DPAPI（密钥绑定当前登录用户），macOS 用登录钥匙串（走系统自带 `security` 命令，此时不留密钥文件）；都只用标准库，不装任何第三方包。仅当系统凭据保护不可用时，才降级为状态目录内的密钥文件（`login.key`，600 权限）。
- 账密用该密钥加密：HKDF-Expand（RFC 5869）派生密钥流后与明文异或，再附 HMAC-SHA256 认证标签并校验后解密（Encrypt-then-MAC），每次加密使用新的随机 salt，因此同一明文每次密文都不同。密钥随机生成、不写进代码。**系统凭据保护下，拿到状态目录本身不足以解密**（拷到别的机器或其它用户都无效）；降级到文件时密钥与密文同目录，能读取该目录的程序或使用者即可解密。macOS/Linux 保留目录 700、文件 600 权限。
- 文件包含有效登录凭据，不能共享或提交；本机可读取该文件的程序也能使用凭据。
- AI 不直接读取 auth-status.json 文件，只调用 auth-status/auth-wait 获取安全摘要，不查看登录页面截图或请求，不使用文档中的旧示例 Token。
- logout 删除本机缓存及账密密文，不撤销服务端令牌；等待登录窗口可能重新创建缓存，先关闭或等待其过期。
- 原始服务端错误可能回显凭据，脚本只输出概括错误。401 自动重登一次，失败再人工登录；不能把403等一律视为过期。

## 非敏感选择

项目/任务、数据缺口、剩余工时、最终确认均优先使用**当前宿主实际支持**的原生交互工具。桌面有弹窗/卡片就用；CLI（Command Line Interface，命令行界面）有交互选择也优先用。以工具说明及运行模式为准，不调用不可用工具。

原生选择不可用时显示1、2、3供回复；数值可回复“1，32小时”。所有常规缺口集中到最终预览处理，不为选项目、选任务、分工时分别停顿。异步问题必须等待真实回复，超时不是批准。

凭据始终通过外部登录输入，不能使用会把内容返回模型的原生输入框。
