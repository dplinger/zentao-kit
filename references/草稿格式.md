# 草稿格式

宿主模型生成 UTF-8 JSON，保存到本次 ~/.zentao-worklog/runs/<run>/plan.json，不放入用户文件站或共享包。示例编号仅用于说明，不能直接使用：

```json
{
  "account": "已鉴权账号",
  "start": "2026-09-07",
  "end": "2026-09-11",
  "hours_policy": "fill8",
  "remaining": {},
  "rows": [
    {
      "date": "2026-09-07",
      "execution": 2,
      "task": 3147,
      "work": "完成问答接口参数校验调整并验证。",
      "consumed": null,
      "sources": ["codex:来源记录ID及日期"],
      "match_reason": "用户指定任务编号，查询确认属于该执行。"
    }
  ]
}
```

- start/end：闭区间，单日相同；默认本周一至今天。account 来自 whoami。
- 每条只对应一个日期；已匹配时填写 task 与 execution，同日可多条、同任务可跨日。未匹配时 task/execution 留空，预览显示“待关联”，但仍自动填写 consumed 和默认 left=8；该行不能提交，用户在预览中指定任务后重新计算。
- 每天通常 2–5 条工作项，最多 8 条；每条对应一件能独立说清的工作，同一工作方向的过程动作（提交推送、同步安装目录、清理、打包上传等）并入所属工作项，不单列，不为凑条数重复或虚构。超过 8 条的草稿会被 `prepare` 拒绝。
- consumed：用户明确值填写数字；未知为 null，fill8 按当日 8 小时总量**整数粗分**差额，扣除明确工时及所选任务内已有工时，如 3 条分 8 小时为 3/3/2；条数少时单条可为 8 小时。确定超过8小时不强行缩减。
- hours_source：可写用户提供的依据；未知分配自动标注。用户改数值时同步改依据。
- sources：记录ID或“用户补充：现场测试……”；不含密码等秘密。
- match_reason：关联依据；多个候选标注 needs_review，放到完整预览一并选择。
- left 由脚本计算，不在草稿直接手写；已关联任务展示逐条计算值，未关联任务展示“8小时（预览默认）”。已完成、已关闭、已取消任务会被解除关联并显示“待关联”，防止写日志后重新激活任务。left 永远必须大于 0；余额不足、刚好归零、缺失或计算异常时统一使用固定剩余 8 小时。

如果用户补充了**本次所选任务以外已经登记**的工时，在草稿顶层增加如下字段。脚本按日扣除该值后再补足8小时，预览单独列出；这些工时不会再次提交。不可把已自动查到的所选任务工时重复填入。

```json
"other_logged_hours": {
  "2026-09-07": {"hours": 3, "reason": "用户确认当天已在缺陷上登记3小时，不属于本次所选任务"}
}
```

本例当天剩余待分配5小时。用户修改补充工时后也必须重新生成预览。

## 剩余不足

默认不足或登记后将归零时，自动生成固定剩余8小时的建议，用户在最终预览确认；也可改为登记前可用总预算，但计算结果仍不得为 0：

```json
"remaining": {"3147": {"mode": "budget", "hours": 32, "reason": "用户选择本次登记前可用32小时"}}
```

三条各8小时，则提交 left 为 [24,16,8]。

用户选择每条登记后固定剩余8小时：

```json
"remaining": {"3147": {"mode": "fixed8", "reason": "用户选择每条登记后固定剩余8小时"}}
```

提交 left 为 [8,8,8]，最终任务仍剩8小时。具体状态和累计工时影响需首次实例验证。

## 确认与恢复

prepare 返回 review 和表格路径；获得用户明确确认后，submit 的 --review/--confirm 传相同摘要。摘要不能替代人类批准。

修改草稿、账号、站点或远端状态需重新预览。跨任务无事务；成功批次不能自动撤销。收据记任务级状态，重跑同一 review 跳过已验证批次，未知批次只回查不重发。

用户明确放弃尚未提交的预览时，使用 `workspace.py cleanup --run <run> --review <review> --discard`。没有收据属于正常的未提交状态，可以清理；任何同草稿收据存在时都必须停止清理并先回查，不能把“没有收据”误报成工作区故障。

清理边界以当前 `ZENTAO_WORKLOG_HOME` 或默认 `~/.zentao-worklog/` 的解析结果为准。只允许处理该根目录内部的实体文件和运行目录，拒绝符号链接及越界目标；删除动作必须进入系统回收站/废纸篓，平台没有可用回收站能力时停止并保留，不得用永久删除兜底。

## 缺项草稿

允许 work/task/execution/sources/match_reason 暂空；候选归属未确定时填 `needs_review` 说明。prepare 返回 draft_incomplete，不能提交。日期范围内未列出的日期也会列入缺项；用户明确排除后记录 `excluded_dates`，例如 `{"2026-09-08": "用户确认休息不登记"}`。不得自行填写用户尚未给出的排除依据。用户解决后移除 needs_review，再生成最终预览。
