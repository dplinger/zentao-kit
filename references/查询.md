# 只读查询任意实体

用 `query` 命令读取需求、待办、测试单、用例、产品计划、项目集、产品、用户，**一个命令覆盖全部实体，只需换 `--entity`**。全部只读，不写入任何数据。

```text
python <技能目录>/scripts/zentao.py entities
python <技能目录>/scripts/zentao.py query --entity stories --product 1
python <技能目录>/scripts/zentao.py query --entity stories --id 1001
```

先跑 `entities` 自省可查实体与各自需要的范围参数，不必猜实体名。

## 命令参数

| 参数 | 说明 |
|---|---|
| `--entity` | 必填，实体名（见下表） |
| `--id` | 给出编号时改查该条详情 |
| `--product` / `--project` / `--execution` | 查询范围；哪些实体需要哪些参数由 `entities` 列出 |
| `--status` | 按状态筛选，**包含即命中**（`已关闭` 能匹配 `已关闭`，`closed` 匹配 `closed`） |
| `--keyword` | 按关键词筛选，匹配记录里所有短文本字段（标题、名称、姓名、账号等） |
| `--limit` | 最多返回条数，默认 20 |
| `--all` | 返回全部命中记录，扫描上限 500 条 |

## 实体与范围

| `--entity` | 含义 | 范围参数 | 单条详情 |
|---|---|---|---|
| `stories` | 需求 | `--product` / `--project` / `--execution`（三者选一） | 有 |
| `todos` | 待办 | 无（固定查当前登录人） | 有 |
| `testtasks` | 测试单 | `--product`（可省略，省略即全部） | 有 |
| `testcases` | 用例 | `--product`（必需） | 有 |
| `plans` | 产品计划 | `--product`（必需） | 无（列表已含全部字段） |
| `programs` | 项目集 | 无 | 有 |
| `products` | 产品 | 无 | 有 |
| `users` | 用户 | 无 | 有 |
| `bugs` | Bug | `--product` / `--project` / `--execution`（三者选一） | 有 |

**`bugs` 是「人的视角」的兜底通道**：`bugs` 命令查的是「我的地盘 → 我的 Bug」页面（当前用户视角），而本命令走 REST 资源视角，必须给产品、项目或执行之一。实测 REST 里**没有**「我的 Bug」等价入口（`v1/v2 tasks`、`v2/my/*` 均 403，`v2/bugs` 返回的是浏览页元数据而非列表），所以页面不可用时用这条通道顶替；反之要「分给我的 Bug」则只能用 `bugs` 命令。

## 实测要点（依据企业版 12.7 与开源版源码）

**筛选一律在本地完成。** 实测 v1 接口的 `status` 过滤参数不生效——传 `status=active` 返回 0 条，而同一批数据里明明有 active 需求。因此服务端只负责范围和分页，状态与关键词由脚本在已读取的记录里筛，行为可预期且跨版本一致。代价是要多读几页，故设 500 条扫描上限；命中数超过 `--limit` 时结果里会说明「命中 N 条，仅显示前 M 条」。

**范围编号会先做存在性预检。** 实测教训：编号写错时部分接口（如产品下的用例）**不报错，而是忽略该参数把全部数据返回**——用户会拿到看似有效、实则与所问无关的结果。脚本在查询前先验证产品/项目/执行编号存在，不存在当场报错。

**分页风格按接口区分，脚本已各自处理**：v1 用 `page`/`limit`（总数在响应顶层 `total`），v2 用 `pageID`/`recPerPage`（总数在 `pager.recTotal`）；项目集接口忽略分页参数，一次返回全量。分页出现重复记录即报错停止，不输出错乱数据；读取不完整时在 `message` 里说明「该范围共 N 条，本次仅读取前 M 条」。

**输出做了可读性处理**：人员字段（`openedBy`、`assignedTo` 等）是嵌套对象，压成 `账号（姓名）`；ISO UTC 时间戳按个人时区换算，避免看到差 8 小时的时间；描述类字段（需求描述 `spec`、测试单说明 `desc` 等）去掉 HTML 标签并截断——接口里的正文是富文本，原样输出会把大量标签灌进对话。

**同一字段在不同端点格式不同**：待办的日期与时间在列表里是 `2026-10-16` / `09:00`，在单条详情里却是 `20261016` / `0900`。脚本统一格式化为前者，避免同一实体的同一个字段换个命令就变样。

**空结果与结构变化必须区分**：`status: empty` 表示该范围确实没有记录（或筛选未命中，`message` 会写明扫描了多少条）；响应里缺少预期的集合字段会直接报错，绝不当作「没有数据」。

## 不做的事

- **不按人查**。本命令是**资源视角**——必须先给出产品 / 项目 / 执行的编号。要问「**我的**需求 / 我的测试单 / 我的 Bug / 我的任务」，用 [我的视图](我的视图.md) 的 `mine` 命令（或 `bugs`、`candidates`），它们走「我的地盘」页面，用当前登录身份作答。

- **不提供写入**。本命令只读；任务、Bug、需求、待办、产品/项目/执行、测试单/用例的写入各有独立流程（见 [任务操作](任务操作.md)、[Bug处理](Bug处理.md)、[需求操作](需求操作.md)、[待办操作](待办操作.md)、[产品项目执行操作](产品项目执行操作.md)、[测试线操作](测试线操作.md)），未接通写入的实体不会用猜测的字段提交。
- **不做统计汇总**。这里只按条件列出记录；项目/执行/产品/Bug 的进度分布与个人年度产出走 [统计报表](统计报表.md) 的 `report` 命令。
- **不提供删除**，任何实体都没有。
- **不猜状态含义**。接口返回英文状态码（`active`、`draft`）或中文状态（`已关闭`）都原样给出，不擅自翻译。
