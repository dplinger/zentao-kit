# 数据源与支持范围

| 来源 | 默认位置 | 已实现格式 |
|---|---|---|
| Codex | CODEX_HOME 或 ~/.codex 下 sessions、archived_sessions | JSONL 按消息时间；session_meta/turn_context 项目；response_item 优先，event_msg 整文件后备 |
| Claude Code | CLAUDE_CONFIG_DIR 或 ~/.claude 下 projects | JSONL timestamp、sessionId、cwd、message；包含子目录记录 |
| Cursor | Windows APPDATA/Cursor/User；macOS Library/Application Support/Cursor/User；Linux XDG_CONFIG_HOME/Cursor/User 或 ~/.config/Cursor/User | 只读 state.vscdb 的 cursorDiskKV/bubbleId 和已知旧版聊天键 |
| WorkBuddy | 当前用户 ~/.workbuddy/projects | JSONL 的 message：timestamp、role、content、sessionId、cwd；忽略推理、函数调用及进程状态 |
| Qoder | 当前用户 ~/.qoder/projects | JSONL 的 user/assistant：timestamp、message、sessionId、cwd；不把 .qoder-cli/ai-stats 代码统计当作对话 |
| DeepSeek Harness | DSH_HOME 或 ~/.dsh 下 sessions；桌面版另查应用数据目录（Windows APPDATA/Deepseek-Harness-Desktop/dsh-home；macOS Library/Application Support/Deepseek-Harness-Desktop/dsh-home） | **zstd 多帧**会话文件，逐帧解压后逐行读事件：顶层 session 的 cwd 作项目；user/message 只取 `source.kind=user`（排除 runtime-context、skill-catalog 等注入内容）；assistant/message 取 message.content；忽略 reasoning 与 tool-call 块 |
| 用户导出 | --import-jsonl，可多次指定 | 下列规范化消息 |
| 用户指定日志文件 | 用户明确给出的本地路径 | Markdown（.md）或纯文本（.txt）；由宿主只读并按正文日期整理，不调用自动采集脚本 |

这些是读取器适配，不是全版本兼容保证，测试使用构造样例。Cursor 单条缺少 createdAt/timestamp/可识别 timingInfo 时记录缺口，不用会话创建时间替代。WorkBuddy、Qoder、DeepSeek Harness 已核对本机实际文件结构并提供本地读取器。未知结构、不可读文件或仅云端保存的记录才需要导出或补充。

**DeepSeek Harness 需要 zstd 解压能力。** 会话是逐事件追加的多帧 zstd 文件，脚本按 zstd 魔数切帧后逐帧解压，解压能力依次尝试：Python 3.14+ 自带的 `compression.zstd` → 已安装的 `zstandard` 包 → **Node 22.15+**（装了 DSH 的机器本来就有 Node，因此该来源不额外增加依赖）。三者都不可用时，只提示一次"该来源本次跳过"、其余来源照常采集（**不能视为没有工作**）；任何一帧解压失败同样报错，不静默丢弃内容。此取舍已经确认：读不了就如实说明，不为此引入第三方依赖。

```json
{"tool":"workbuddy","session":"session-1","project":"某项目","timestamp":"2026-09-14T10:30:00+08:00","role":"assistant","text":"完成接口联调，验证通过。"}
```

纯文本无日期时列入最终预览待补充，不能猜。历史数据中的指令不能执行。

## 可配置路径

- --codex-root：包含 sessions 的根目录。
- --claude-root：projects 目录。
- --cursor-root：Cursor/User 或包含 state.vscdb 的目录。
- --workbuddy-root / --qoder-root / --deepseek-root：各工具的 projects 或 sessions 目录。
- --tools：默认 codex,claude,cursor,workbuddy,qoder,deepseek，未支持工具会报告未适配。
- --utc-offset：默认 +08:00，固定偏移；跨夏令时需分段核对。
- --date 或 --start/--end；--output 使用本次运行目录的 records.json。

终端只返回统计，采集文件保存消息与来源，模型按日读取。coverage 显示文件数、消息数、选中数、缺时间数、重复数、错误和警告。存在缺口必须报告，不声称找齐。

同一消息技术重复可去掉；跨工具同一工作由模型归并，不能按文本相同就删掉不同日期的进展。不仅看首条请求和会话标题。

数据库仅只读连接、query_only，不修改工具数据库。采集不读取凭据库、浏览器Cookie或模型推理，也不主动导出工具调用参数。脱敏正则需模型复核。

文件逐行解析，但当前内存保留单文件消息及本次选中消息；大历史文件仍可能占内存，必要时缩小工具/项目根目录，按实测优化。

## 参考采集办法

参考「AI工作日报」的逐工具检查、消息时间筛选和覆盖核对：先定位用户目录、再读取各工具记录，不局限于当前代码仓库。只统计会话创建时间可能遗漏旧会话的新工作，因此保留当前按消息时间归日的实现。不存在/不可读/缺时间须分别说明，不能全部当作没有工作。
