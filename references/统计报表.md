# 统计报表

用 `report` 命令读取禅道内建的统计：项目、执行、产品、Bug 的进度分布，以及按人统计的年度贡献与产出。

```text
python <技能目录>/scripts/zentao.py report                        # 列出可用统计项（无需登录）
python <技能目录>/scripts/zentao.py report --fields projectoverview,bugprogress
python <技能目录>/scripts/zentao.py report --fields radar,output --me --year 2026
python <技能目录>/scripts/zentao.py report --fields executionprogress --limit 5
```

## 命令参数

| 参数 | 说明 |
|---|---|
| `--fields` | 逗号分隔的统计项，可多选；不给则只列出可用项 |
| `--year` | 统计年份，默认今年 |
| `--me` / `--account` | 统计当前登录账号 / 指定账号；两者互斥。**只影响项目概况、雷达、年度产出三项** |
| `--limit` | 明细列表最多列出条数，默认 20，上限 200 |

## 可用统计项

| `--fields` | 含义 | 返回内容 |
|---|---|---|
| `projectoverview` | 项目概况 | 各状态项目数量汇总 |
| `radar` | 年度贡献雷达 | 产品 / 执行 / 研发 / 测试 / 其他五维贡献 |
| `projectprogress` | 项目进度 | 项目列表与进度、工时 |
| `executionprogress` | 执行进度 | 执行列表与进度、工时、延期天数 |
| `productprogress` | 产品进度 | 产品列表 + 需求状态分布 + 进度 |
| `bugprogress` | Bug 进度 | 产品列表 + Bug 状态分布 |
| `output` | 年度产出 | 按操作类型（创建 / 指派 / 完成 / 解决 …）统计的产出 |

## 三个必须知道的点

**这是隐藏接口，不同版本可能不一致。** 走的是 `GET v1/reports`——未进官方文档，实测企业版 12.7 七种统计全部可用；开源版源码中有该条目，但未在开源版实例上实测。取数失败会如实报错，不会假装没有数据。

**接口对未知统计项静默忽略。** 字段名拼错**不会报错**，只会返回空对象——用户会误以为「就是没有数据」。所以统计项一律在**本地白名单校验**，写错立刻报错并列出可用项（与查询层的范围编号预检同一思路）。

**指定账号不会收窄进度类统计。** `account` 只影响 `projectoverview`、`radar`、`output` 三项；`projectprogress` 这类始终是**全公司**的。因此输出里会写明本次统计范围，指定账号且同时取了进度类统计时还会额外提示一次。

## 输出做了截断

明细列表会随记录量线性膨胀（实测可达数百条、50KB 级），直接输出会灌满对话。脚本对项目 / 执行 / 产品 / Bug 四类明细按 `--limit` 截断，并补一个 `total` 表示实际条数，同时在 `message` 里说明「共 N 条，本次只列出前 M 条」。计数型统计（项目概况、雷达、年度产出）数据量小，全部给出。

## 常见用法

- **我今年干了多少**：`report --fields radar,output --me`
- **公司整体项目情况**：`report --fields projectoverview,projectprogress`
- **哪个产品 Bug 多**：`report --fields bugprogress --limit 10`
- **配合周报**：统计得出的数字可作为周报 / 日报的客观依据，写进 [报告导出](报告导出.md) 的本地 Markdown。

## 不做的事

- **只读**，不写入任何数据。
- **不改动统计口径**。接口返回什么就展示什么，不重新计算、不合并、不臆断字段含义；状态码（`doing`、`normal`）与接口给出的中文名都原样保留。
