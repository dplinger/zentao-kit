# 创建、修改、完成与关闭任务

复用 V2 登录及已有项目、执行查询。不能把“完成任务”和“关闭任务”视为同一步，也不能因写日志自动执行任务操作。

## 对话流程

1. 登录后根据用户诉求选择 create、update、finish、close。任务操作模式不采集聊天记录、不套用每日8小时分配。
2. 新建任务先查询 `projects`、`executions --project <编号>`，让用户明确所属执行；修改或流转已有任务先确认编号，可用 `candidates` 或 `tasks --execution <编号>` 列出可选项。查不到不能猜编号。
3. 从需求整理任务标题和描述。未指定时可在预览中建议指派给当前账号、优先级3、开发类型；预计工时、实际完成耗时和日期不能沿用示例或编造。指派他人需其登录账号，不把姓名直接作为账号。
4. 在本次内部运行目录保存任务计划 JSON，调用 `task-prepare --plan <绝对路径>`。预览展示操作类型、任务/执行、字段中文名称及修改前后值。用户要修改则重新生成预览。
5. 用户确认展示的最终内容后，执行 `task-submit --review <摘要> --confirm <同一摘要>`。回复任务编号、名称和链接。准备开发技能不代表授权执行示例任务。
6. 接口超时、返回失败、创建响应无编号或回查不一致时停止，不自动重发、不换版本、不另建计划重试。操作记录位于 `~/.zentao-worklog/actions/`（所有实体共用同一目录），保留用于核对；全部成功后自动清理操作预览和收据。

## 接口与计划字段

鉴权由客户端携带当前用户 Token，绝不复制文档示例令牌。以下接口前缀均为站点 `/api.php/`。

| action | 方法与路径 | fields |
|---|---|---|
| create | POST v2/tasks | name、executionID、type、assignedTo、pri、estimate；可选 estStarted、deadline、module、story、desc |
| update | PUT v2/tasks/{taskID} | 只在计划里写用户要改的字段；脚本从实时详情补齐其余字段，完整发送，保留原值 |
| finish | PUT v2/tasks/{taskID}/finish | currentConsumed（本次新增消耗）、assignedTo、realStarted、finishedDate |
| close | PUT v2/tasks/{taskID}/close | comment（备注，可为空）；当前仅允许关闭已完成任务 |

create 计划还需 `project` 编号以验证执行归属，其他操作需 `task` 编号。所有计划均包含 `action` 和 `fields`。

```json
{
  "action": "update",
  "task": 3147,
  "fields": {"name": "用户确认的新任务名称", "estimate": 80}
}
```

示例仅演示结构，不代表操作指令。type 支持 design/devel/request/test/study/discuss/ui/affair/misc；pri 为1到4；日期使用 YYYY-MM-DD，预计日期可空。修改的字段为 name/type/assignedTo/estStarted/deadline/pri/estimate/module/story/desc，不支持用此接口迁移执行。需要清空字段时必须用户明确要求，不能把未提供解释成空字符串。

完成/关闭后先通过任务详情只读回查。完成任务会改变任务状态及累计消耗，不等于普通日志登记，不能再把同一次消耗重复写为日志。关闭备注可能不在详情响应中返回，回查确认关闭状态，不能宣称已单独验证备注。
