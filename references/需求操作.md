# 需求操作

用「预览 → 用户确认 → 单次写入 → 回查」两步完成需求的新建、修改、变更、关闭和激活。全程只用 v1 接口。

> **权限要求**：需求的写操作通常属**产品经理角色**。没有权限时接口返回 HTTP 403，
> 脚本会明确提示「当前账号没有需求的写权限，请管理员授权」，请如实转达，
> 不要压缩成「操作失败」。

```text
python <技能目录>/scripts/zentao.py story-prepare --plan <plan路径>     # 只读，生成预览
python <技能目录>/scripts/zentao.py story-submit --review <完整摘要> --confirm <同一完整摘要>
```

## 计划格式

`product` 可放顶层或 `fields` 内；`update/change/close/activate` 用 `story` 指定需求编号。

```text
{"action":"create","product":75,"fields":{"title":"标题","spec":"描述","pri":3,"category":"feature"}}
{"action":"update","story":1001,"fields":{"pri":2,"keywords":"关键词"}}
{"action":"change","story":1001,"fields":{"title":"新标题","spec":"<p>新描述</p>"}}
{"action":"close","story":1001,"fields":{"closedReason":"willnotdo","comment":"不再需要"}}
{"action":"activate","story":1001,"fields":{"assignedTo":"your-account","comment":"重新启用"}}
```

## 各操作的端点与字段

| 操作 | 方法与本路径（接 `/api.php/`） | 允许的字段 | 必填 |
|---|---|---|---|
| 新建 | `POST v1/stories` | title、spec、verify、pri、category、estimate、plan、module、source、sourceNote、keywords、type、stage、product | **title、spec、pri、category** |
| 修改 | `PUT v1/stories/{id}` | 同上（除 product 由详情带出） | 至少一个字段 |
| 变更 | `POST v1/stories/{id}/change` | title、spec、verify、comment | title |
| 关闭 | `POST v1/stories/{id}/close` | closedReason、duplicateStory、comment | closedReason |
| 激活 | `POST v1/stories/{id}/active` | assignedTo、status、comment | 无 |

- **修改用 PUT，状态流转用 POST**——与 Bug 的状态流转一致（该站点 PUT 会返回 200 却静默失败）。
- `category` 常见取值：`feature`、`interface`、`performance`、`safe`、`experience`、`improve`、`other`；脚本不硬校验取值，以便兼容不同发行版。
- `pri` 为 1 至 4。`closedReason` 常见取值：`done`、`duplicate`、`postponed`、`willnotdo`；选 `duplicate` 时必须同时给 `duplicateStory`。
- `spec`（描述）等字段按富文本处理：纯文本会自动包成段落，已含 HTML 标签的原样保留。预览里显示的是去掉标签并截断后的摘要，写入用的仍是完整内容。

## 状态前置条件（预览阶段就拦住）

| 操作 | 允许的当前状态 |
|---|---|
| 修改 / 变更 | 不能是 `closed`（需先激活） |
| 变更 | `active`、`reviewing`、`changing`、`draft` |
| 关闭 | `active`、`reviewing`、`changing` |
| 激活 | 只能是 `closed` |

## 权限：403 就是权限不足

**需求的写权限通常属于产品经理角色**，开发或测试账号常见无权限。实测开发账号对需求的创建、修改、关闭、激活、指派、评审**全部返回 403**，而对照的假路由返回 404、Bug 与任务的写返回 400 或成功——说明路由存在，只是缺权限。

因此脚本遇到 403 时不再笼统报「无权访问」，而是明确告诉用户：

> 当前账号没有需求的写权限（HTTP 403），本次操作未执行。需求的创建、修改、关闭、激活通常属于产品经理角色权限，请让禅道管理员为该账号授予需求相关权限后重试。

**如实转达这条提示**，不要压缩成「操作失败」。授权确认后重试即可，脚本已保留操作记录、不会自动重发。

## 写入后的处理

- 写入前重新读取需求详情，与预览时的指纹比对；**预览后有人改过就拒绝写入**并要求重新预览。
- 写入后重新读取详情核对：产品归属、状态、以及请求的每个字段。修改时还会逐项核对**未请求的字段是否被改动**（服务端用旧值兜底，但发现漂移就报出具体字段名）。
- 结果不明（超时、响应异常）时保留收据并**禁止重发**，只能只读回查。同一份预览不允许执行两次。
- 不提供删除需求的能力。
